# Contributing

This is a source-free engineering case study published under an all-rights-reserved license. The license does not grant permission to modify the material or create derivative works, so unsolicited pull requests cannot be accepted.

## Start with an issue

Open an issue before doing any work if you want to report:

- a supportable factual, spelling, link, or accessibility problem;
- wording that overstates or obscures an implemented boundary;
- a diagram or navigation problem; or
- a weakness in the public publication audit.

Describe the reader-facing problem and the smallest useful correction. The maintainer may implement it directly. Do not fork or prepare a modification in anticipation of acceptance.

If the maintainer wants an external contribution, the scope and written contribution terms must be agreed before work begins. An issue discussion, fork, or pull-request interface is not itself a license or permission grant.

## Out of scope

Do not submit application or upstream source, binaries, archives, catalogs, catalog rows, real titles or descriptions, credentials, local paths, browser profiles, cookies, tokens, conversations, screenshots, HAR files, full diagnostics, or third-party material without reviewed redistribution rights.

## Before opening an issue

1. Keep claims within the evidence documented in [`docs/verification-evidence.md`](docs/verification-evidence.md).
2. Label every fabricated example clearly.
3. Give every image meaningful alternative text.
4. Ensure SVGs include `<title>` and `<desc>` elements and contain no scripts or remote resources.
5. Do not include patches, replacement files, screenshots, or private implementation evidence unless the maintainer has explicitly requested them under agreed written terms.

Use [private vulnerability reporting](https://github.com/NouraldinFarge/research-studio-case-study/security/advisories/new)—not an issue or pull request—for security or privacy concerns.
