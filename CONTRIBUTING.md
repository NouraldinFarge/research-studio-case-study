# Contributing

This is a source-free engineering case study published under an all-rights-reserved license. The license does not grant permission to modify the material or create derivative works, so unsolicited pull requests cannot be accepted.

## Feedback and changes

Public issues are not enabled and unsolicited pull requests cannot be accepted. This keeps the contribution surface consistent with the all-rights-reserved license and the repository's private-evidence boundary.

If the maintainer explicitly invites a documentation correction, the scope and written contribution terms must be agreed before work begins. A fork or pull-request interface is not itself a license or permission grant.

## Out of scope

Do not submit application or upstream source, binaries, archives, catalogs, catalog rows, real titles or descriptions, credentials, local paths, browser profiles, cookies, tokens, conversations, account/browser captures, real-data screenshots, HAR files, full diagnostics, or third-party material without reviewed redistribution rights. Invited synthetic product captures must be reproducible from the documented fabricated fixture and contain no local path or account pane.

## Before an invited change

1. Keep claims within the evidence documented in [`docs/verification-evidence.md`](docs/verification-evidence.md).
2. Label every fabricated example clearly.
3. Give every image meaningful alternative text.
4. Ensure SVGs include `<title>` and `<desc>` elements and contain no scripts or remote resources.
5. Do not include patches, replacement files, visuals, or private implementation evidence unless the maintainer has explicitly requested them under agreed written terms.

Use [private vulnerability reporting](https://github.com/NouraldinFarge/research-studio-case-study/security/advisories/new)—not an issue or pull request—for security or privacy concerns.
